版本：v0.1  
日期：2026-07-04

## 1. 产品定位

ClipFlow 是一个面向个人视频创作者的视频剪辑创作工作平台。

它不是传统剪辑软件，也不是一开始就全自动 Agent 平台。第一阶段要解决的是：把一条视频从想法、脚本、录制、封面、剪辑、归档、平台数据复盘的全过程，做成可见、可交互、可复用的工作流产品。

当前产品由四个核心模块组成：

- 主 Dashboard：总览本月创作、待办、最近视频、封面精选和数据入口。
- 创建视频工作流：以管道方式一步步完成视频日记制作。
- 封面画廊：管理生成封面和参考封面，沉淀风格资产。
- 数据看板：用月度平台快照补录播放、点赞、评论、收藏等数据。

## 2. 背景与问题

用户已经在 Codex 中跑通了一套视频日记工作流，但它还依赖对话、文件夹和人工记忆。

当前痛点：

- 每次创作都要在 Codex 里微调流程，不能稳定复制给别人。
- 原始想法、脚本、封面、字幕、成片、日志分散在不同目录。
- 封面风格靠临时判断，缺少可复用画廊。
- 视频制作完成后，制作耗时和平台表现难以统一复盘。
- 合规检视、脚本改稿、封面确认、剪辑归档这些节点没有产品化状态。

ClipFlow 要把这些隐性的工作流变成一个显性的本地创作工作台。

## 3. 目标用户

第一目标用户：

- 有持续短视频创作需求的个人创作者。
- 希望保留自己表达风格，而不是让 AI 完全替代写作。
- 希望把视频制作流程标准化，降低每天重复制作成本。
- 愿意先用本地工具管理素材、脚本、封面和复盘数据。

暂不服务：

- 专业多人剪辑团队。
- 需要完整时间线剪辑能力的用户。
- 多账号投放团队。
- 需要实时平台数据监控的运营团队。

## 4. 产品目标

MVP 目标：

1. 提供一个可操作的创作入口，让用户按步骤创建新视频。
2. 提供一个主 Dashboard，让用户知道本月创作情况和下一步动作。
3. 提供一个封面画廊，让生成封面和参考封面可以被管理和复用。
4. 提供一个数据看板，用月度快照方式补齐平台反馈。
5. 提供一个 Run Detail，让用户回看某条视频完整工作流。

非目标：

- 不做完整 NLE 剪辑器。
- 不做实时平台 API 抓取。
- 不做多用户权限系统。
- 不做拖拽式工作流编排。
- 不在第一版接入真实 AI Agent 自动执行。

## 6. 核心工作流

创建视频的主流程：

```text
输入内容
-> 脚本检测
-> 人工改稿
-> 上传视频
-> 封面确认
-> 制作参数
-> 剪辑流转
-> 数据归档
```

每个步骤都必须有：

- 当前状态
- 用户输入或系统输出
- 下一步动作
- 对应产物
- 可回看路径

## 7. 功能需求

### 7.1 主 Dashboard

目标：作为创作工作台入口。

必须展示：

- 本月范围。
- 本月制作数、本月发布数、总视频时长、总制作时长、导出总大小。
- 本月平台快照指标：播放、点赞、评论、收藏、快照补录覆盖率。
- 最近视频列表。
- 待处理事项。
- 精选封面。
- 创建视频、封面画廊、数据看板、Run Detail 的入口。

规则：

- 平台数据必须标注来自“手动月度快照”。
- 缺失平台快照时显示“待补录”，不能当作 0。
- 最近视频可以先读样例 JSON，后续再接真实数据源。

### 7.2 创建视频工作流

目标：把视频制作做成可交互管道。

步骤需求：

1. 输入内容
   - 输入内容日期。
   - 输入视频标题。
   - 粘贴当天想法、口述稿或粗糙文本。

2. 脚本检测
   - 检测敏感词、平台风险和高风险表达。
   - 返回命中词和处理建议。
   - 支持退回修改或继续生成脚本。

3. 人工改稿
   - 展示生成脚本。
   - 用户可以直接修改脚本。
   - 支持复制脚本。
   - 用户确认后进入视频上传。

4. 上传视频
   - 选择或登记本地视频文件。
   - Demo 阶段只记录文件名。
   - 后续接入本地文件导入。

5. 封面确认
   - 支持选择封面模板。
   - 支持选择视频候选主图。
   - 支持手动上传主图。
   - 支持编辑主标题、副标题、视频时长文案。
   - 生成封面预览。
   - 用户确认后进入制作参数。

6. 制作参数
   - 输入视频时长。
   - 输入文件大小。
   - 输入去掉片头秒数。
   - 输入去掉片尾秒数。

7. 剪辑流转
   - 展示剪辑任务状态：
     - 去掉片头/片尾
     - 生成字幕
     - 字幕校对
     - 脚本检视
     - 生成视频
     - 保存封面和成片
   - 支持模拟执行状态。
   - 如果脚本检视命中风险，进入人工确认分支。
   - 用户可选择继续，或退回脚本修改。

8. 数据归档
   - 展示最终视频路径。
   - 展示封面路径。
   - 展示视频时长。
   - 展示制作时长。
   - 展示日志路径。

### 7.3 Run Detail

目标：回看一条视频的完整工作流。

必须展示：

- Step Timeline。
- 当前 Step 的 input / output。
- Step 状态。
- 该 Step 产生的 Artifacts。
- Workflow Version。
- Gate 信息。
- Known Issues。

规则：

- `Compliance Agent` 的结果应该作为 `Gate` 展示，不作为普通生产 Step。
- Artifact 必须挂到生产它的 Step。
- 后续应支持从 Dashboard 最近视频跳转到真实 Run，而不是全部指向 Day 28。

### 7.4 封面画廊

目标：沉淀封面风格资产。

必须支持两类素材：

- `generated`：每次工作流生成的封面。
- `reference`：用户从外部收藏的参考封面。

必须展示：

- 分组标题。
- 分组说明。
- 封面图片。
- 封面标签。
- 来源类型。
- 分类。
- 备注。

后续需求：

- 从创建流程确认封面后，自动进入画廊。
- 支持按栏目、日期、风格筛选。
- 支持把参考封面转成模板。
- 支持关联平台表现，判断封面风格是否值得延续。

### 7.5 数据看板

目标：让平台反馈进入复盘闭环。

第一版不做实时抓取，只做月度平台快照。

必须展示：

- 统计范围。
- 平台名称。
- 已校对快照数。
- 待补录数。
- 视频列表。
- 播放量、点赞、评论、收藏、分享。
- OCR / 校对状态。
- 截图路径。

规则：

- `null` 表示待录入，不显示为 0。
- 平台数据必须有截图或手动录入证据。
- OCR 是增强能力，不阻塞 MVP。
- 数据看板服务月度复盘，不服务实时监控。

## 9. Agent 与 Gate 设计

当前产品保留三个源工作流 Agent：

| Agent | 产品角色 |
| --- | --- |
| `Compliance Agent` | 输入和输出合规 Gate |
| `Text Agent` | 原始想法、脚本生成、人工改稿辅助 |
| `Video Agent` | 封面、字幕、剪辑、导出、日志 |

规则：

- Agent 第一阶段可以是 mock，不需要真实执行。
- Skill 是步骤能力，不是常驻 Agent。
- 合规结果放在 `Gate.result`，不要混入 Step 状态。
- 所有关键节点保留人工确认。

## 10. 验收标准

MVP 可验收条件：

- Dashboard 可以看清本月创作、待办、最近视频、封面精选和数据入口。
- `/create` 可以完整走完 8 步 Demo 管道。
- `/gallery` 可以展示生成封面和参考封面。
- `/metrics/snapshots` 可以展示已校对和待补录平台快照。
- `/runs/run_2026_06_30_day28` 可以展示 Step Timeline 和 Artifact。
- 缺失数据不被误展示为 0。
- 所有页面使用本地样例数据可运行。

## 11. 版本规划

### v0.1：可演示工作台

- 主 Dashboard。
- 创建视频 Demo 管道。
- Run Detail。
- 封面画廊。
- 平台数据快照看板。
- 本地 JSON 样例数据。

### v0.2：本地数据接入

- 从真实 `00_state` 读取制作数据。
- 从真实 `15_cover_gallery` 读取封面。
- 创建流程生成结构化 Run 草稿。
- 最近视频跳转到真实 Run。

### v0.3：手动录入闭环

- 平台快照手动录入表单。
- 截图路径记录。
- 月度复盘汇总。
- 缺失快照提醒。

### v0.4：轻量 Agent 接入

- 脚本检测接真实规则。
- 封面生成接真实脚本或模板。
- 剪辑步骤接本地工具执行状态。
- Compliance Gate 结构化记录。

## 12. 暂不做

- 多用户登录。
- 云端存储。
- 拖拽式工作流编排。
- 完整视频时间线剪辑器。
- 平台 API 实时同步。
- 自动发布。
- 大规模封面表现归因。

## 13. 风险与约束

- 本地文件路径和浏览器访问路径需要统一映射。
- 视频、封面、字幕文件可能很大，不能把媒体文件直接塞进 JSON。
- 平台指标缺失必须和数值 0 区分。
- 合规判断需要人工确认，不能让模型自动决定发布。
- Demo 数据和真实数据源之间需要一层稳定转换，不能在页面里散落解析逻辑。
